    Approach

    How I build agents

    Writes wait for a person

    In my Calendar and Gmail agent, any tool that creates, updates, deletes or sends pauses for Approve or Deny. Reads go straight through.

    Take the dangerous tool away

    If an assistant only needs to read, it gets no write path at all. A jailbroken prompt in RestaurantOS has nothing to call.

    Stream the whole turn

    Users see tokens, tool searches and speech as they happen, over SSE or WebSockets, instead of waiting for a finished answer.

    Make accounts hard to probe

    A wrong password and an unknown email return the same message, and someone else's session id returns the same 404 as a missing one.
